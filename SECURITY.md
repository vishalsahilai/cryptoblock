# Security

Do not disclose passwords, tokens, private account exports or full request headers in public issues. For a suspected vulnerability, use the repository's private vulnerability-reporting feature if enabled; otherwise ask the maintainer for a private reporting channel without posting exploit details or secrets.

Server-verified Supabase identity controls D1 account access. Exports/backups may contain personal information; never make the R2 bucket public. Standalone hosting must keep public MCP writes disabled. Apply pending dependency/security updates and retest authentication before public launch.
